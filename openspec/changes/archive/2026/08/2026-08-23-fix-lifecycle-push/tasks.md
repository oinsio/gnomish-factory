## 1. Shared push core (`adapter.git.remote`, design D2)

- [x] 1.1 Spec + implement the origin reader in `adapter.git.remote`: presence check and URL read over the injected `GitProcessRunner`; absorb `OriginRemoteUrl` (move/rename, update its callers). FR1 groundwork, M3
  - **Deviation from design D2's package placement, taken across all of section 1.** The core lives in `adapter.git` itself (`OriginRemote`, `RefspecPush`, `RemoteBranchTip`, plus `LocalBranchTip`), not in an `adapter.git.remote` subpackage. `GitProcessRunner.run` and `GitCommandResult` are package-private on purpose — the git seam is not part of the adapter's outward surface — and a subpackage would have forced both public, widening the raw subprocess seam to every module that imports the adapter (against NFR-S1). D2's actual requirement, one construction site per primitive, is met and gated by `RemotePrimitiveSingleSiteSpec` and `NoForcePushGuardSpec`; only the package name differs.

## 3. Tier 2 — origin reconciliation at touchpoints (design D3)

- [x] 3.1 Spec + implement the reconciliation check in `adapter.git.remote`: local tip taken as a parameter, one remote-refs read, best-effort catch-up push when origin is behind or missing the branch, never throws, WARN on failure, catch-up logged. FR3, NFR-R1, NFR-O1, NFR-C1
- [x] 3.2 Wire the resume-start touchpoint (host and container resume bootstraps), each mode supplying its native local tip. FR3
- [x] 3.3 Wire the terminal-boundary touchpoint. FR3
  - **Host parks are exempt: the tier-3 fence supersedes the check.** `GitOutcomeRecorder` skips the terminal-boundary reconciliation for `Escalated`/`Paused`, because `TakeEngineExecution` runs the fence over the same unchanged tip immediately afterwards — same origin gate, same `ls-remote`, and a push with a bounded re-attempt where the reconciliation pushes once. Running both spent a second round-trip that could change nothing (NFR-C1). `Completed`/`Aborted` run no fence (NG6) and keep the reconciliation as their only level-based net. The park predicate lives once, in `TerminalPark`, read by both decisions.
  - **Container mode wires it on the keep boundary, not per recording arm.** `ContainerRunTermination.keepStopped` carries the reconciliation alongside `completeAndDispose`'s, because a container park (`Escalated`/`Paused`) records no lifecycle commit and therefore reaches no recording arm at all — it goes straight from the engine's outcome to "keep the box stopped". Placing the touchpoint there covers park, abort-keep, and EOF-interrupted dialogs in both `take` and `run` with one call site, and every caller of `recordAborted` follows it with `keepStopped`, so no boundary reconciles twice.
- [x] 3.4 Resolve design Q1: trace whether any fresh-claim path bypasses resume bootstrap; wire or record the finding in this task's completion note. Q1
  - **Finding: no. The default (resume-start only) stands.** `TakeWorkRouter.locateAndWork` routes on `git.branches().locate(...)`: any task whose branch exists locally, as a remote-tracking ref, or on origin goes to the resume arm, which funnels into `TakeResumeBootstrap` (host) or `TakeContainerResumeBootstrap` (container) — both now carry the resume-start touchpoint. Only `BranchLocation.NotFound` reaches a fresh claim, and a task with no branch anywhere has no commit to reconcile: its first lifecycle commit is `createTask`, covered by tier 1's edge push. So no fresh-claim path bypasses the check in a way that could leave origin behind.
- [x] 3.5 Integration spec: crash-shaped fixture (terminal commit local, origin behind) healed by a resume's touchpoint check; unreachable origin degrades to WARN without blocking. FR3, M1

## 4. Tier 3 — delivery fence before a park's tracker write (design D4)

- [x] 4.1 Spec + implement the fence as a thin sibling of `RemoteAttemptDelivery` over the shared core: verify tip delivered → push → one bounded re-attempt → structured delivered/undelivered verdict; silent no-op without origin. FR4, NFR-R2
- [x] 4.2 Wire the fence into the host park exit between `recordOutcome` and the terminal tracker write; on exhaustion the park proceeds and the park report gains a one-line origin-behind note. FR4, FR5, UX2
  - **Also wired into the DEFERRED park.** `TakeDispositionResume`'s orphaned-park reconcile re-posts a park through the same exits, so it runs the same fence and carries the same note. The resume-start touchpoint ahead of it is best-effort and swallows its own failure, so without the fence an unreachable origin would produce a re-posted park that reads as replicated. `TakeResumeReplicationSpec` covers both verdicts on that path.
- [x] 4.3 Integration spec: park with transient-then-successful push lands on origin before the tracker write observes it (bare-origin + tracker fake reading origin at write time); unreachable origin parks anyway with the note and WARN. M2, FR5, NFR-O1
  - **Split across three specs, one per claim.** M2's "origin already carries the park when the write runs" is `TakeParkOriginOrderingSpecBase`/`InMemoryTakeParkOriginOrderingSpec`: a real `take` run against a real bare origin, where the tracker reads `ls-remote` from inside its own `park` and the spec asserts the commit found there is the park commit (recorded `escalated` outcome, `trackerWritePending` set). The transient-then-successful push and the unreachable-origin note/WARN are `ParkDeliveryFenceSpec` against the same bare-origin fixture; the ORDER of fence-then-write across the routing chain is `TakeResumeReplicationSpec`. One spec covering all three would have to drive a real `take` run whose origin fails exactly once, which the fake-agent fixture cannot stage without a hook rewrite per scenario.

- [x] 5.7 Scrub remote-URL credentials from git's captured stderr at the subprocess seam, so no push/refs failure can carry an `origin`-embedded token into a WARN or a tracker-published report detail. NFR-S2
  - **Finding: the leak is real but not the one review reported.** Git 2.55 anonymizes remote URLs in its transport diagnostics — an unresolvable host, a 404, an authentication failure, and a non-fast-forward rejection all print the URL with the entire userinfo stripped (reproduced against a local HTTP git backend and against github.com). The one message that does echo it is the credential *prompt* failure, `could not read Password for 'https://<username>@host'`, which the factory's own runs provoke: an `origin` of `https://<PAT>@github.com/owner/repo.git` plus a subprocess with no controlling terminal. There the username is the token. Fixed at `GitProcessRunner`'s capture point (one choke point, all ~10 stderr-logging sites at once) rather than per WARN.
