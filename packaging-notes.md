# Заметки: упаковка и запуск фабрики (add-factory-packaging)

Рабочие заметки по ходу обсуждения. Простыми словами, без формальностей.
Когда решения устаканятся — переедут в proposal/design на английском.

## Решено

1. **Сама фабрика запускается на хосте**, не в Docker.
   Почему: фабрика запускает agent CLI (`claude`) как обычный процесс,
   ходит в Docker чтобы поднимать песочницы, а на macOS ещё и управляет
   Colima VM — всё это из контейнера делать больно или невозможно.
   Как сервис: systemd на Linux, launchd на macOS.

2. **Команда `gnomish` — это скрипт-обёртка вокруг `java -jar`.**
   Java 25 на машине — честный prerequisite, наравне с Docker, git
   и agent CLI. Самодостаточный пакет со своей Java (jlink) — отложен:
   он почти бесполезен без release-процесса в CI (платформенные архивы,
   smoke-тест дистрибутива, пересборка на security-патчи JDK) — это
   отдельный change, когда появится отдельный Linux-хост.

## Отложено

- **jlink / release-процесс в CI** — до появления отдельного
  Linux-хоста (см. решение 2).
- **Компаньоны (gateway, depot): единый compose-файл, кто их
  запускает, бэкап Postgres** — до реализации sandbox changes.
  Заготовка на будущее: склонялись к «один compose-файл с профилями;
  фабрика проверяет, что компаньоны живы (self-check), но не управляет
  их жизненным циклом»; не забыть бэкап Postgres у gateway (там учёт
  расходов).

## Ещё обсуждаем

- Где лежат настройки и секреты фабрики (токен трекера и т.п.):
  единое каноничное место и правила.
- Граница с пунктом 5 роадмапа (наблюдаемость): packaging отвечает
  только за «умер — перезапустился», не за мониторинг.
- Какие платформы в scope сейчас: macOS + один Linux-хост; k8s и
  публикация образов — не в этом change.

## Полезные факты (выяснили по коду)

- Guard (mitmdump) — не постоянный сервис: фабрика сама поднимает его
  контейнер на каждую задачу. Для упаковки это вопрос сборки образа,
  а не запуска сервиса.
- Постоянные сервисы — только gateway и depot. У gateway есть Postgres
  с учётом расходов — значит, нужен бэкап.
- `gnomish serve` уже умеет аккуратно завершаться (ServeShutdown),
  так что systemd/launchd лягут на готовое.
