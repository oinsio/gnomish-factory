### 3.3 `TrackerReadProbe` behind `--online` — BLOCKED, escalated
- Not built. D3 says the probe uses "the tracker's existing read-only resolution", but `TrackerWiring.resolveReadOnly`/`boardReader` (application/.../TrackerWiring.java:142-158) build the adapter through `factory.create(...)`, and `GithubTrackerAdapterFactory.create` (adapters/github/.../GithubTrackerAdapterFactory.java:123-124) always runs `GithubLabelProvisioner.provision`, which lists labels and POSTs every missing one (GithubLabelProvisioner.java:60,75-81). So the probe would write to the tracker on a repository lacking the labels (against NFR-R1 and the "Online adds a read-only tracker probe" scenario) and always make 2+ requests (the scenario's verification asks for exactly one read). No existing SPI operation of `TrackerAdapterFactory` reads without `create`. Escalated with options A (adapter-owned read-only probe on the SPI), B (read-only mode for `create`), C (rejected).
